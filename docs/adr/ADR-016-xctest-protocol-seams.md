# ADR-016: XCTest only, fakes at protocol/closure seams, no mocking library

**Status:** Accepted
**Date:** 2026-09-28

## Context

ADR-001 rules out third-party packages for the test target as well as the app. The
codebase is nevertheless heavily tested, including its security-sensitive paths, because
every external effect sits behind an injectable seam: protocols such as
`ProcessIdentityReading`, `ProcessSignalSending`, `LsofCommandRunning`,
`BoundedProcessRunning`, `BriefProviding`, `NotificationServicing`, `LoginItemServicing`,
`AlertsPreferenceStoring`, `RunningAppControlling`, `SettingsOpening`,
`PanelSessionHandling` and `PowerAssertionControlling`, plus the collector closures
`SystemMonitor.init` accepts.

Every test double in `Tests/SysBarTests` is a hand-written conformer to one of those
production protocols (for example `ScriptedProcessIdentityReader`,
`RecordingProcessSignalSender`, `StubLsofCommandRunner`, `FakeNotificationService`,
`FakeBriefProvider`, `PanelSessionSpy`) or a substituted closure. None is generated by a
macro or runtime proxy.

## Decision

Test exclusively with XCTest (`@testable import SysBar`) and hand-written fakes built
against existing protocol or closure seams. Add no mocking library.

## Consequences

Easier:

- Every fake is a plain Swift type a contributor can read top to bottom.
- A fake can only conform to a protocol production code also depends on, which keeps the
  seams honest: you cannot mock a method that is not part of an injectable interface.
- Process actions, the `lsof` scan and the AI CLI boundary are fully testable without
  touching a real process, signal or subprocess in CI.

Harder:

- Every new seam needs a hand-written double, kept in sync with the protocol.
- Types with no seam (`SystemMonitor` itself, `AppDelegate`, the AppKit button wiring, the
  live Darwin collectors) are tested through their internal surface or left as known
  coverage gaps covered only by the manual release checklist.
